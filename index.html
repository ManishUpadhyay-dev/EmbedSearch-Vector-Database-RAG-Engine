Setup & Run Guide

Step-by-step instructions to configure MSYS2, Git, Ollama models, and compile the C++ engine.

The 3 Required Prerequisites

Before running Nish: Own AI on Windows, ensure you have these three tools installed:

1. MSYS2 (g++ Compiler) Download ↗

Gives you the MinGW-w64 UCRT64 toolchain to compile C++17 with native Winsock networking.

2. Git for Windows Download ↗

Used to clone the project repository, pull submodules, and track revisions.

3. Ollama (Local AI) Download ↗

Runs nomic-embed-text (768D embeddings) & llama3.2 locally on your GPU/CPU with 0 cloud API fees.

STEP 01

Install MSYS2 & Configure g++ PATH

Download the installer from msys2.org, keep default path (C:\msys64), then open MSYS2 UCRT64 from Start Menu.

pacman -Syu

Install the MinGW-w64 UCRT64 GCC toolchain:

pacman -S mingw-w64-ucrt-x86_64-gcc
Add g++ to Windows PATH:
1. Press Win + R, type sysdm.cpl, press Enter.
2. Click Advanced → Environment Variables.
3. Under System variables, select Path and click Edit.
4. Click New and add: C:\msys64\ucrt64\bin, then click OK.
5. Open a new PowerShell terminal and verify:
g++ --version
STEP 02

Install Git

Download Git from git-scm.com and run installer with default settings.

git --version
STEP 03

Install Ollama & Pull Required Models

Download and install from ollama.com. Ollama runs in your system tray. Pull both required models in PowerShell:

1. Pull document embedding model (~274 MB, generates 768-D vectors):
ollama pull nomic-embed-text
2. Pull language model (~2 GB, synthesizes answers from retrieved context):
ollama pull llama3.2
3. Verify models are ready:
ollama list
💡 Laptop Spec Tip: Minimum 8GB RAM is recommended. If llama3.2 is slow on your CPU, pull the lighter 1B model: ollama pull llama3.2:1b and change genModel in main.cpp.
STEP 04 & 05

Clone & Compile the C++ Engine

Clone the repository, enter the directory, and compile with g++ using C++17 and Winsock networking:

git clone https://github.com/ManishUpadhyay-dev/EmbedSearch-Vector-Database-RAG-Engine.git cd EmbedSearch-Vector-Database-RAG-Engine

Compile the server (takes ~15 seconds):

g++ -std=c++17 -O2 main.cpp -o db -lws2_32
-std=c++17 : C++17 standard • -O2 : compiler optimization • -o db : binary output name • -lws2_32 : Windows Winsock networking
STEP 06

Run Everything & Launch Web Studio

Open two separate PowerShell terminal tabs to run the Ollama daemon and Nish: Own AI server:

Terminal 1 — Start Ollama:
ollama serve
Terminal 2 — Start the C++ Vector Engine:
./db

What This Project Does

A fully working AI-powered vector database built in C++ with a web UI. Implements HNSW, KD-Tree, and Brute Force search algorithms side-by-side, plus a RAG pipeline powered by a local LLM via Ollama.

Feature Specification & Description
3 Search Algorithms HNSW (production-grade), KD-Tree, Brute Force — run all three side-by-side and compare speed.
3 Distance Metrics Cosine similarity, Euclidean distance, Manhattan distance.
16D Demo Vectors 20 pre-loaded semantic vectors across 4 categories (CS, Math, Food, Sports).
2D PCA Scatter Plot Live visualization of semantic space — watch high-dimensional clusters form in real-time.
Real Document Embedding Paste any text → Ollama embeds it with nomic-embed-text (768D normalized dense vectors).
RAG Pipeline Ask questions about your documents → HNSW retrieves context → local llama3.2 answers.
Full REST API CRUD endpoints: insert, delete, search, benchmark, hnsw-info, stats.

How It Works

Your Text
    │
    ▼

    │
    ▼
HNSW Index (C++)                   ← indexes the vector in a multilayer graph
    │
    ▼
Semantic Search                    ← finds nearest neighbors in vector space
    │
    ▼
Ollama (llama3.2)                  ← reads retrieved chunks, generates an answer
    │
    ▼
Answer

HNSW (Hierarchical Navigable Small World) is the same algorithm used by Pinecone, Weaviate, Chroma, and Milvus. It builds a multilayer graph where each layer is progressively sparser — searches start at the top layer and zoom in, achieving O(log N) complexity instead of O(N) for brute force.

Using the Application

TAB 1 — SEARCH (DEMO VECTORS)

Type any concept: binary tree, sushi, basketball, calculus. Choose algorithm (HNSW, KD-Tree, Brute Force) and distance metric (Cosine, Euclidean, Manhattan). View live PCA clusters and run microsecond comparisons.

TAB 2 — DOCUMENTS (768D EMBEDDINGS)

Paste textbook excerpts, lecture notes, or articles. Long documents are automatically split into overlapping 250-word chunks. Each chunk receives its own 768D embedding via Ollama and is indexed into HNSW.

TAB 3 — ASK AI (RAG PIPELINE)

Ask questions about your inserted documents. Your question is embedded, HNSW finds the top-K most semantically similar chunks, and llama3.2 synthesizes answers streamed with a typewriter effect.

Algorithm Deep Dive

HNSW (Hierarchical Navigable Small World)

Nodes are inserted into a multilayer graph. Each node randomly gets assigned a maximum layer. Layer 0 contains all nodes with dense local connections; higher layers have exponentially fewer nodes with long-range connections.

Insert: Start at the top layer, greedily find the nearest node, drop down a layer, and repeat. At each layer from the assigned maximum down to 0, run a beam search (ef_construction=200) and bidirectionally connect to the M nearest neighbors.
Search: Same greedy descent from the top layer. At Layer 0, expand to ef nearest candidates using a priority queue.
Why it's fast: The upper layers act like a highway network — you rapidly zoom into the correct semantic neighborhood, then execute fine-grained local navigation at Layer 0.

KD-Tree (K-Dimensional Tree)

Binary space partitioning. Each node splits vector space along one coordinate axis (cycling through dimensions 0 through D-1). Search prunes entire subtrees when the closest possible point in that subspace cannot beat the current best distance — the ball within hyperslab geometric check.

Curse of Dimensionality Weakness: While KD-Tree achieves O(log N) in 2D or 3D, its pruning degrades exponentially as dimensionality climbs. At 16 dimensions pruning is rare, and at 768 dimensions (Ollama embeddings), KD-Tree degrades entirely into a linear scan (brute force).

Why HNSW Wins at High Dimensions

KD-Tree pruning relies on axis-aligned distance bounds. In high-dimensional spaces, nearly all volume is concentrated near the surface of the hypersphere — resulting in every bounding box overlapping the query hypersphere and preventing subtree pruning. HNSW navigates graph topology instead of coordinate bounding boxes, making it immune to the curse of dimensionality.

Model Selection & Performance Tuning

How to switch to smaller or faster local LLMs for low-latency laptop inference (from README.md):

If llama3.2 takes more than 15–20s on CPU, pull the lightweight 1B parameter model:

ollama pull llama3.2:1b

Then update line 71 in main.cpp:

std::string genModel = "llama3.2:1b"; // fast 1B parameter model

Recompile with g++ -std=c++17 -O2 main.cpp -o db -lws2_32 and restart.
